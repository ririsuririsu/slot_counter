## 2. 殲滅モード

### 2-1. 5種のモード

通常時を管理する内部モード。**CZ天井**と**各ゲーム数での殲滅ZONE当選期待度**が変わる。

| モード | CZ天井 | 到達経路 |
|---|---|---|
| リセット | 350G+α | 設定変更時のみ |
| 通常A | 550G+α | CZ後 / AT後 |
| 通常B | 450G+α | CZ後 / AT後 |
| 通常C | 250G+α | CZ後 / AT後 |
| 通常D | 150G+α | CZ後 / AT後 |

**リセットは遷移先にならない。** 設定変更時の開始状態専用なので、
リセット回と判断した行では隠れ状態ではなく**既知の状態**として扱える（強いアンカーになる）。

### 2-2. モード移行率 — AT後【全設定共通】

| 移行先 | 振り分け |
|---|---|
| 通常A | 12.50% |
| 通常B | 25.00% |
| 通常C | 12.50% |
| **通常D** | **50.00%** |

### 2-3. モード移行率 — CZ後【設定差あり】★設定推測の主軸

| 設定 | 通常A | 通常B | 通常C | 通常D | （通常B以上） |
|---|---|---|---|---|---|
| 1 | 50.0% | 20.0% | 15.0% | 15.0% | 50.0% |
| 2 | 48.7% | 21.3% | 15.0% | 15.0% | 51.3% |
| 3 | 42.5% | 22.5% | 17.5% | 17.5% | 57.5% |
| 4 | 37.5% | 22.5% | 20.0% | 20.0% | 62.5% |
| 5 | 26.2% | 23.8% | 22.5% | 27.5% | 73.8% |
| 6 | 20.0% | 25.0% | 25.0% | 30.0% | 80.0% |

全設定で合計100.0%になることを検算済み。

**この表から直ちに分かること**

- **設定1と設定2はほぼ同一**（通常C・通常Dは完全に同値、A/Bが1.3ポイント違うだけ）。
  この軸で1と2を分けるのは事実上不可能。
- **設定3と設定4も通常C=通常D**の構造。分かれるのは通常Aの5ポイントのみ。
- 効くのは**高設定 / 低設定の二分**。通常Aの 50.0% vs 20.0% が2.5倍の尤度比を持つ。

**サンプル効率**（モードが完全に観測できる理想ケース・CZ失敗1回あたりの期待log₁₀BF）

| 比較 | 1回あたり | BF=100 に必要なCZ失敗回数 |
|---|---|---|
| 設定6 vs 設定1 | +0.0904 | **約22回** |
| 設定6 vs 設定4 | +0.0339 | 約59回 |
| 設定5 vs 設定6 | +0.0050 | 約404回 |
| 設定1 vs 設定2 | +0.0003 | 約7,981回 |

実際にはモードが部分観測なのでこれより遅い。**隣接設定の判別には使えない**ことを
UIに明記する。

**重要**: 設定差があるのは **CZ後** だけ。AT後は全設定共通なので、
AT当選が続く展開では設定の情報がまったく増えない。
サンプル効率は総サイクル数ではなく **CZ失敗回数** で決まる。

## 3. 殲滅ZONE当選期待度マップ ★モード推測の主観測

規定ゲーム数ごとの殲滅ZONE当選期待度。**これがモードの出力（emission）になる。**

| ゲーム数 | リセット | 通常A | 通常B | 通常C | 通常D |
|---|---|---|---|---|---|
| 50G | 50.0% | 25.0% | 50.0% | 25.0% | **100%** |
| 100G | 25.0% | 50.0% | 1.3% | 50.0% | 1.3% |
| 150G | 50.0% | 1.3% | 50.0% | 1.3% | **CZ天井** |
| 200G | ← タチコマSAMゾーン（§3-2） → | | | | — |
| 250G | 50.0% | 50.0% | 25.0% | **CZ天井** | — |
| 300G | 抽選なし | 抽選なし | 1.3% | — | — |
| 350G | **CZ天井** | 25.0% | 50.0% | — | — |
| 400G | — | ← タチコマSAMゾーン → | | — | — |
| 450G | — | 50.0% | **CZ天井** | — | — |
| 500G | — | 抽選なし | — | — | — |
| 550G | — | **CZ天井** | — | — | — |

- **CZ天井到達時は殲滅ZONEを経由して SAM（CZ）以上当選濃厚**。実質100%として扱う。
- 「抽選なし」は殲滅ZONEの当選抽選が存在しないゲーム数（300G・500G）。darukun 氏が
  「300Gが死にゾーン」と書いているのはこれ（通常Bの1.3%以外は当たらない）。
- 「—」はそのモードが既にCZ天井に達しているため到達しえない。
- 規定ゲーム数からの殲滅ZONE前兆開始時は**液晶のゲーム数表記の色が変化する**
  （前兆かどうかを目視で切り分けられる）。

### 3-1. この表から導かれる設計上の要点

**(a) 通常Aと通常Cは250Gまで完全に同一**（25.0 / 50.0 / 1.3%）。
MonhanRise のモードA↔Cと同じ問題で、250Gを超えるまで直接には分離できない。
分離するのは通常CのCZ天井（250G+α）に到達するかどうか。

**(b) 50Gの非当選は通常Dを完全に否定する**（通常Dは50Gで100%当選）。
一様事前での1観測の効き方:

| 観測 | リセット | 通常A | 通常B | 通常C | 通常D |
|---|---|---|---|---|---|
| 50G 当選 | 20.0% | 10.0% | 20.0% | 10.0% | **40.0%** |
| 50G 非当選 | 20.0% | 30.0% | 20.0% | 30.0% | **0.0%** |
| 100G 当選 | 19.6% | 39.2% | 1.0% | 39.2% | 1.0% |
| 100G 非当選 | 20.1% | 13.4% | 26.5% | 13.4% | 26.5% |

**(c) 非当選は当選と同じくらい情報を持つ。** 1.3% のマスを素通りしても何も分からないが、
50%・100% のマスを素通りするのは強い否定になる。だから入力UIは
「通過したが当たらなかった」を**入力ゼロで表現できる形**にする必要がある（§7-1）。

**(d) CZ天井は尤度0のハード制約。** そのモードの天井を超えて未当選なら、
そのモードは消える。確率表を使わずにモードが確定することがある。

```
250G を超えて CZ未当選 → 通常C・通常D が消滅
350G を超えて CZ未当選 → リセット も消滅
450G を超えて CZ未当選 → 通常B も消滅 → 通常A 確定
```

### 3-2. タチコマSAMゾーン（200G / 400G）

200G・400G は殲滅ZONEではなく、**CZ「タチコマの家出」の抽選ゾーン**。
モードの出力ではないので、**モード推測の尤度には入れない**。

設定差あり（AT終了後の200G＆400G到達時の合算値）:

| 設定 | 当選率 |
|---|---|
| 1 | 30.0% |
| 6 | 48.3% |

設定2〜5 は未取得。「AT終了後」という条件が全モード共通なのか、
AT後サイクル限定なのかは**未確認**。実装前に要確認。

### 3-3. 当選回数が事前決定される点【モデル上の注意】

出典の注記:

> 本機は、モード決定時にゾーンでの殲滅ZONE当選期待度に応じて先に、
> 最深部まで消化した場合、何回殲滅ZONEに当選するかを決定している。

つまり**各ゾーンの当否は独立試行ではない**。モード決定時に「何回当たるか」が先に決まり、
その回数に合うようにゾーンが割り振られている。

- 各マスの**周辺確率**は上表のとおりで正しい
- しかし1サイクル内の複数マスを**掛け算するのは近似**になる（相関を無視している）
- 同時分布は公開されていないので、独立と仮定する以外に扱いようがない

実装では独立と仮定し、**その旨をコードのコメントとUIの注記に残す**。
相関の符号が分からないため、過信・過小のどちらに転ぶかも不明。
モードごとの期待当選回数は リセット1.75 / A 2.01 / B 1.78 / C 0.76 / D 1.01 回。

アイキャッチ演出が「殲滅ZONE保有個数」を示唆するのは、この事前決定された回数のこと。
ただし具体的な示唆内容（素子＝3個以上、2ndGIG＝5個以上 等）は
Web要約から拾った値で**裏が取れていない**ため、確定情報として扱わない。

## 4. 推定モデル

### 4-1. モードは記憶を持たない — HMMではない【実装時に判明】

当初はMonhanRise軸3と同じ隠れマルコフモデルを想定していたが、**出典の移行率表は
「移行先」の1次元しかない**（移行元のモードが表に現れない）。つまり次のモードは
直前のモードに依存しない。

その結果:

- **各サイクルのモードは独立した抽選**になる。マルコフ連鎖ですらない
- forward / forward-backward / Viterbi は**すべて不要**。各サイクルを単独で解けばよい
- **後のサイクルの観測が手前のモードを絞り込むことはない**。MonhanRise では
  「モードD確定 ⇒ 手前はC」のような遡及があったが、この機種では起こらない

```
設定 s の対数尤度 = Σ_cycle log( Σ_mode prior(mode) × emission(mode, 観測) )
設定の事後分布    P(s) ∝ exp(logL(s))          （一様事前）
サイクルのモード事後 ∝ prior(mode) × emission(mode, 観測)  （設定事後で重み付け平均）
```

**prior はサイクルごとに切り替える。** 前の行の終わり方で決まる。

| 前の行の終わり方 | 使う振り分け | 設定差 |
|---|---|---|
| CZ失敗 | §2-3 CZ後 | **あり** |
| CZ成功 → AT → AT終了 | §2-2 AT後 | なし |
| 殲滅ZONEからAT直撃 → AT終了 | §2-2 AT後 | なし |
| AT間999G天井 → AT終了 | §2-2 AT後 | なし |
| リセット回 | リセット 100%（隠れ状態ではなく既知） | — |
| **直前が不明**（途中から拾った台・打ち切りの後） | **通常A〜D 均等** | なし |

**「直前が不明」を均等にしているのは意図的。** 移行率表（CZ後）をそのまま事前分布に
使うと設定差のある分布になり、「どう始まったか分からない」という**仮定だけで設定の
事後が動いてしまう**。CZ後の通常Aは設定1と6で2.5倍違うので、1行の未知の始まりが
実測4〜5サイクル分の重みを持つ。観測ではなく仮定なので載せない。
（MonhanRise は定常分布を使っているが、あちらは遷移が真にマルコフで
定常分布に意味がある。この機種では「定常分布＝移行率表そのもの」なので事情が違う。）

### 4-2. 1サイクルの出力尤度

そのサイクルのモードを m、到達ゲーム数を G とすると:

```
P(観測 | m) = ∏ 到達済みの規定G数 g について
                 当選した g なら Z[m][g]
                 素通りした g なら (1 − Z[m][g])
              ただし
                 タチコマSAMゾーン（200G/400G）は除外
                 「抽選なし」（300G/500G）は除外
                 未到達の g（g > G）は除外
                 CZ天井を超えていたら尤度 0
```

**打ち切り（やめ）も有効な観測。** 「400Gまで回して未当選でやめた」は
通常C・通常Dとリセットを消す強い情報なので、到達Gさえ記録すれば右側打ち切りとして効く。
MonhanRise 軸2 が打ち切り入力を廃止したのは5値すべてが観測できる性質があったためで、
この機種には当てはまらない。

### 4-3. 尤度から除外するもの

| 対象 | 理由 |
|---|---|
| 殲滅ポイント（撃破数）契機のゾーン | 規定ゲーム数ゾーンではないのでモードと無関係 |
| タチコマSAMゾーン（200G/400G） | 殲滅ZONEではない。別軸（§5-2）で扱う |
| 色 | 色は撃破ptと殲滅テーブルで決まる。**モードとは無関係**（§6） |
| 色・当否が未入力のセル | 値を null にして枠は残し、尤度からのみ外す |

### 4-4. 示唆演出の扱い

**「濃厚」はハード制約として尤度に乗せる。振り分け数値が不要だから。**
「示唆」は振り分けが不明なので**表示のみ**にする。数値を捏造しない。

| 画面 | 扱い |
|---|---|
| 素子（後姿）＝モードB以上濃厚 | 通常A・リセットの尤度を0に |
| 公安9課（赤枠）／電脳素子（紫枠）＝モードC以上濃厚 | 通常A・B・リセットを0に |
| アオイ（金枠）＝モードD濃厚 ＋ 設定4以上濃厚 | モードを通常Dに固定、設定1〜3を0に |
| ポーカー＝高モード示唆 | 表示のみ |
| 素子（戦闘中）＝高設定示唆（弱） | 表示のみ |
| トグサ＝奇数 / バトー＝偶数 | 表示のみ |

制約が観測と矛盾したら（例: モードD濃厚なのに200Gまで未当選）、
**制約を自動で外して警告を出す**。入力ミスで全設定・全モードが尤度0になる事故を防ぐ。

最強モード示唆リールフラッシュ」。

## 6. 殲滅ZONEの色

**色はモードを反映しない。** ここを取り違えると設計全体が狂う。

- 色 ← 累積撃破ポイント（殲滅テーブル7種）とゾーンの通し番号
- モード ← どのゲーム数にゾーンが配置され、各ゾーンの当選期待度がいくらか

色は「そのゾーンからCZに入る期待度」＝**設定差要素**（§5-4）であって、モードの手掛かりではない。
モードを絞るのは**G数**。だからグリッドの主軸はG数で、色は属性として並置する。

| 色 | 発展先 | CZ当選期待度（設定1 → 設定6） |
|---|---|---|
| 白 | BATTLE | LOW |
| 青 | BATTLE | 3.8% → 9.6% |
| 緑 | 屋上 | 20.0% → 30.4% |
| 赤 | 屋上 | 55.0% → 61.7% |
| 紫 | ラッフィングマンルーム | 75%以上 |
| 金 | 殲滅CHANCE | S.A.M.以上濃厚!? |
| 虹 | 殲滅CHANCE HYPER | AT以上濃厚!? |

**殲滅テーブル（7種）** — 累積撃破ptの帯でテーブルが決まり、1〜7個目の色列を決める。
取得できた断片のみ:

| pt帯 | 色列（1個目→7個目） |
|---|---|
| 0〜19pt | 白 → 青 → 青 → 青 → 緑 → 赤 → 紫 |
| 20〜39pt | 青 → 緑 → 緑 → 緑 → 赤 → 紫 → 金 |
| 100pt以上 | 金 → 金 → 金 → 虹 → 虹 → 虹 → 虹 |

40〜99pt の4テーブルは未取得。

## 7. 入力UI

### 7-1. グリッド

**縦＝CZサイクル / 横＝規定ゲーム数の固定10列。**

ご要望は「横が殲滅ゾーン」だが、**n個目ではなくG数を列に固定する**ことを推奨する。

1. §3 の表と列が1対1なので、グリッドがそのまま尤度の入力図になる
2. **非当選が入力ゼロで表現できる**（§3-1(c)）。通過済みなのに空のセル＝そこで非当選、
   という情報がタップ操作なしに手に入る。n個目を列にするとこれが表現できない
3. 列が動かないので、行が増えても同じG数が同じ位置に並ぶ

```
             50   100  150  200  250  300  350  400  450  550   pt   結果
1回(リセット) 青◎  ─    ─    ─    ─    ─    ─    ─    ─    ─         SAM失敗 →HACK×
2回           ・   ・   赤◎  ─    ─    ─    ─    ─    ─    ─         SAM失敗 →HACK○ →AT
3回           ・   ・   ・   タチ  ・   ・   白    ・   青◎  ─   緑   タチコマ成功 →AT
4回           ・   ▓▓ ← 入力待ち（現在 120G）

凡例  ・ 通過・非当選   ─ 未到達   ◎ このゾーンからCZ当選   ▓ 次に埋まる位置
      タチ = タチコマSAMゾーン（200G/400G・モード推測には使わない）
      pt列 = 殲滅ポイント契機のゾーン（同上）
      300G/500G は「抽選なし」なので常に淡色で固定

推定モード: 通常A 71% / 通常B 24% / …   ← 3回が450Gを超えて未当選 → C・D・リセット消滅
```

**列の見せ方**

- 50/100/150/250/350/450/550 … 殲滅ZONEの規定G数（タップ可）
- 200/400 … タチコマSAMゾーン（別色。当否は記録するがモード尤度に入れない）
- 300/500 … 抽選なし（淡色固定・タップ不可。ただし通常Bの300Gだけは1.3%で当たりうる）
- 各モードのCZ天井位置にマーカーを出し、到達したら「そのモードが消えた」と分かるようにする

### 7-2. セルの入力 — ゲーム数カウンターは回さない

**入力はすべてセルのタップで完結する。** 液晶のG数を追いかけてカウンターを進める運用は取らない。
**到達Gはタップしたセルの位置から決まる。**

```
到達G = max( 記録済みゾーンの最大G, 「ここまで通過」の指定G, 締めた行の endGame )
```

セルをタップ → モーダル。**G数はセルの列位置そのものなので入力しない。**

| 項目 | 内容 |
|---|---|
| **◯◯Gまで通過（非当選）** | 未到達のセルで出る。ここまで回して殲滅ZONEが出なかった、という観測になる |
| 到達Gをここまで戻す | 到達済みのセルで出る。押しすぎたときの巻き戻し |
| 色 | 白 / 青 / 緑 / 赤 / 紫 / 金 / 虹 / 未入力 |
| CZ当選 | ○（このゾーンからCZ突入） / ×（非当選） |
| 殲滅ZONE発生を記録 | 記録すると到達Gもそのセルまで自動で伸びる |
| 削除 | 記録を消す＝非当選に戻す |

**未到達のセルもタップできる。** 250Gでゾーンが出たら250Gのセルを押すだけでよく、
そこまでの50/100/150Gは「通過したが非当選」として自動的に観測に入る。
途中でゾーンが1回も出なければ、到達したところのセルを押して「◯◯Gまで通過」を選ぶ。

到達Gは上部にも出していて、ずれたときだけ直接編集できる。
**記録済みゾーンのG数を下回ることはない**（ゾーンが出た事実の方が強いため）。

セルの見た目は3状態:

| 表示 | 意味 |
|---|---|
| 色つきチップ | 殲滅ZONE発生（◎付きはそこからCZ当選） |
| `・` | 通過したが非当選 ＝ **観測として尤度に効く** |
| `—` | 未到達（タップすれば到達にできる） |

**列が固定なので、MonhanRise で必要だった2つの規則が不要になった。**

- 「編集できるのは次の1マスだけ」…… 不要。位置がずれないので到達済みの列は自由に編集できる
- 「削除しても枠は残す」…… 不要。削除＝そのゲーム数で非当選、という正しい観測になる

- セルは `events` 配列の添字を保持し、訂正・挿入・削除はその添字で行う
- リセット回は行の先頭タップで切り替える二値。既定は1行目のみリセット回
- 到達Gは「記録済みゾーンの最大G」を下回らないようにしている。
  現在Gの更新を忘れても、入力済みのセルが「未到達」に化けない

### 7-3. 行（CZサイクル）の記録

| 項目 | 選択肢 |
|---|---|
| CZ種別 | S.A.M. / タチコマの家出 / なし |
| CZ結果 | 成功 / 失敗 |
| 視覚HACK | 発生 / 非発生（CZ失敗時のみ） |
| AT突入経路 | CZ成功 / 殲滅ZONE直撃 / AT間999G天井 / なし |
| 到達G数 | 打ち切り時のみ。未当選でやめたG数（§4-2） |

### 7-4. 画面示唆 — カタログは2系統

**同じキャラでも系統で示唆が違う**ので、idを分けて別カタログにしている
（ウインドウのトグサ＝奇数示唆／CZ終了画面のトグサ＝高設定示唆（弱））。

#### (a) ウインドウ — CZ終了時のPUSH押下 / AT終了 / 裏コマンド

**モード示唆と設定示唆が混在する。**

| 画面 | 枠 | モード示唆 | 設定示唆 |
|---|---|---|---|
| 素子 | 緑 | 基本パターン | — |
| 素子（戦闘中） | 緑 | — | 高設定示唆（弱） |
| トグサ | 緑 | — | 奇数設定示唆 |
| バトー | 緑 | — | 偶数設定示唆 |
| ポーカー | 緑 | 高モード示唆 | — |
| 素子（後姿） | 緑 | **モードB以上濃厚!?** | — |
| 公安9課 | **赤** | **モードC以上濃厚!?** | — |
| 電脳素子 | **紫** | **モードC以上濃厚!?（強）** | — |
| アオイ | **金** | **モードD濃厚!?** | **設定4以上濃厚!?** |
| 2ndGIG | 緑 | — | 白の境界（上位CZ）権利保有時の専用画面 |

#### (b) CZ終了画面 — CZが終わってそのまま出る方

**モード示唆は無く、すべて設定示唆。**

| 画面 | 示唆 | 制約 |
|---|---|---|
| 青空 | 基本パターン | — |
| 青空＋笑い男マーク | 復活期待度 50% | —（設定示唆ではない） |
| 青空＋公安9課 | **設定2以上濃厚!?** | 設定1を否定 |
| オペ子 | 奇数設定示唆 | — |
| タチコマ | 偶数設定示唆 | — |
| トグサ | 高設定示唆（弱） | — |
| イシカワ | 高設定示唆（強）／出現頻度 9.4〜18.8% | — |
| 素子 | **設定1・4・5・6濃厚!?** ＋ 高設定示唆（強） | **設定2・3だけを否定**（飛び飛び） |
| バカンス | **設定4以上濃厚!?** | 設定1〜3を否定 |
| 全員集合 | **設定6濃厚!?** | 設定1〜5を否定 |

**出現手順（UIに明記する）**

- CZ終了時: そのまま (b)。**PUSHボタンを押すと (a) に切り替わる**
- AT終了時: (a) がそのまま出る
- **裏コマンド: 通常時77G経過かつ全リール停止後に左ボタン7回押下**
  （リプレイ・レア役成立時／前兆中は無効）→ リール右側のUIに出現 → (a)

**裏コマンドが使える意味は大きい。** CZ/AT終了を待たずに**任意のタイミングでモードを
覗ける**ので、モード示唆はサイクル終端の属性ではなく**サイクル途中にも置ける独立イベント**
として持たせる。77G以降ならいつでも記録できるよう、グリッドとは別に常設の記録ボタンを置く。

#### 出現場面はカタログとは別軸

**「どの一覧の画面か」と「どの場面で見たか」は別物**なので、分けて持つ。
カタログは画面IDから決まり、場面はユーザーが選ぶ。

| 場面 | タグ | カタログ |
|---|---|---|
| CZ終了画面 | `CZ` | CZ終了画面 |
| CZ終了＋PUSH | `PUSH` | ウインドウ |
| AT終了 | `AT` | ウインドウ |
| 裏コマンド | `裏` | ウインドウ |

ウインドウは3通りの出し方があり、同じ画面でもどれで見たかが記録の裏取りに要る
（`KokakuScreenEvent.occasion`）。入力UIの選択肢は場面の4択だけで、
カタログの切り替えも兼ねる。グリッドのセルにはサムネイルとこのタグを出す。

保存データの場面がカタログと食い違っていたら、`normalizeKokakuEvents` が
そのカタログで成立する既定の場面へ寄せる。旧形式の `context`
（`'cz-end' | 'window' | 'at-end' | 'ura-command'`）もここで読み替える。

#### どのサイクルの示唆か【重要】

**モードはサイクル終了時に引き直される。** したがって終了時に出た画面は、
締めたサイクルではなく**次のサイクル**のモードを示唆している。

| いつ見た画面か | どのサイクルの示唆か | 入力場所 |
|---|---|---|
| サイクル途中の裏コマンド（77G以降） | **そのサイクル自身** | 常設の「裏コマンドの画面を記録」パネル |
| CZ終了画面 / AT終了画面 / 終了直後の裏コマンド | **次のサイクル** | 「サイクルを締める」モーダル内の「終了時の画面」 |

実装はイベントの**位置**だけで表現している。専用のフィールドは持たない。

```
… zone … [screen] … [cycle-end] [screen] … zone …
           ↑ このサイクル          ↑ 次のサイクル
```

`buildKokakuGrid` は `cycle-end` で行を切り替えるので、直前に置けばその行、
直後に置けば次の行に属する。締めと同時に記録した場合も、
`cycle-end` を先に積んでから `screen` を積むので自動的に次の行へ入る。

**設定示唆どうしの矛盾**は積集合が空になった時点で検出し、制約を丸ごと捨てて警告する
（`settingConflict`）。なお現在のカタログはすべての制約が設定6を含むので、
実データで矛盾は起きない。将来この性質が崩れる画面を足したら経路が実際に届くようになる
（テストで不変条件として固定してある）。

**ゾーンを1つも記録していない行でも画面示唆は効く。** 裏コマンドは77G以降なので、
ゾーンより先に示唆だけが入る展開が普通にある。`hasObservation` で到達G0を早期リターン
してはいけない（実装当初これで制約が丸ごと無視されていた）。
モード濃厚は移行率経由で設定にも効く（モードDは設定1で15%、設定6で30%）。

#### 画面キャプチャ

ピッカーは `public/kokaku-screens/<画面ID>.webp` のサムネイルを出す。
**20枚すべて配置済み（合計244KB、WebP）。** `vite.config.ts` の `globPatterns` に
`webp` を足してあるのでプリキャッシュされ、オフラインでも画面選択が使える。

画像が無い場合は**実機の枠色を再現したカード**にフォールバックする。
読み込み失敗を `onError` で拾うだけなので、画像の有無を設定する必要はない。

差し替え手順とファイル名の一覧は
[public/kokaku-screens/README.md](../public/kokaku-screens/README.md)。権利表記は ©Sammy。

### 7-5. 到達ゲーム数の持ち方

**この機種は `currentGame` を持つ。** MonhanRise は4軸すべてがゲーム数を使わないため
`totalGames` を持たなかったが、攻殻機動隊は**ゲーム数が主観測**なので必要。

ただし**ユーザーが手で進めるカウンターではない**。セルのタップ（§7-2）が

- 進行中の行 → `currentGame`
- 締めた行 → `cycle-end.endGame`

のどちらかを書き換える。専用のイベント種別は増やしていない。
ずれたときだけ上部の到達G表示から `DrumPicker` で直接直せる。

**サイクルを締めると `currentGame` は0に戻る**（次のサイクルは0Gから）。
締めた行の到達Gは `endGame` に残るので観測は失われない。
途中の行の締めを訂正する `updateKokakuEventAt` は `currentGame` を触らない。

### 7-6. 画面構成

```
ヘッダー（台選択）
├ 入力タブ
│  ├ 進行中サイクルの到達G（セルタップから導出・タップで直接編集も可）
│  ├ 推定モード分布 ＋ 次ゾーンの当選期待度
│  ├ 殲滅ZONE履歴グリッド（§7-1）
│  ├ 「◯回目のサイクルを締める」ボタン
│  │   （結果セルは横スクロールの右端で隠れるため、表の下にも出す）
│  └ 終了画面・裏コマンドの記録（折りたたみ）
└ 推測タブ
   ├ 設定推測（CZ後移行率による事後確率）
   ├ 殲滅モードの履歴（サイクルごとの分布）
   ├ 出現した示唆（画面の集計。§7-7）
   └ 参考：実測値（設定1/6の基準値と並記。%は出さない）
```

### 7-7. 出現した示唆の集計

推測タブに、記録した画面を**種類ごとに数えて**並べる。
並びはカタログ順（弱い示唆→強い示唆）で、画面選択と同じ順で読める。

各行が持つもの:

| 要素 | 内容 |
|---|---|
| サムネイル | 56px。`public/kokaku-screens/<id>.webp`、無ければキャラ名 |
| 回数 | `×N` |
| 示唆 | モード示唆／設定示唆。制約に入っている行は文字を強調 |
| 左の枠色 | 実機の枠色。**色つき（赤・紫・金）＝「濃厚」＝制約に反映済み** |
| 出現場所 | `4回 裏` のチップ。サイクル番号＋場面タグ |
| 見出しの合計 | 総件数と、**デフォルト画面（素子・青空）以外の件数** |

**チップの「◯回」は示唆が掛かっているサイクル**であって、見たタイミングではない。
終了時に見た画面は次のサイクルに属する（§7-4）ので1つずれる。UIにも注記する。

デフォルト画面の判定は `KokakuScreenInfo.defaultPattern`。文言（'基本パターン'）の
文字列一致に頼らない。なお「デフォルト以外の割合」に設定別の基準値は無いので、
実測値を出すだけで期待度は示さない。

モード遷移の表示は `MonhanRiseModePath` の作りを踏襲する
（Viterbi で1本、forward-backward の確度で薄字、現在モードは分布全体を積み上げバー）。

## 8. データモデル案

```ts
export type KokakuMode = 'reset' | 'normalA' | 'normalB' | 'normalC' | 'normalD';
export type KokakuZoneColor = 'white' | 'blue' | 'green' | 'red' | 'purple' | 'gold' | 'rainbow';

/** 殲滅ZONEの規定ゲーム数。200/400はタチコマ、300/500は抽選なしなので含めない */
export const KOKAKU_ZONE_GAMES = [50, 100, 150, 250, 300, 350, 450, 550] as const;
export const KOKAKU_TACHIKOMA_GAMES = [200, 400] as const;
/** モード別CZ天井。この値を超えて未当選ならそのモードは尤度0 */
export const KOKAKU_CZ_CEILING: Record<KokakuMode, number> =
  { reset: 350, normalA: 550, normalB: 450, normalC: 250, normalD: 150 };

export type KokakuEvent =
  | { type: 'cycle-start'; reset: boolean }
  /** 規定ゲーム数契機の殲滅ZONE。game は KOKAKU_ZONE_GAMES のいずれか */
  | { type: 'zone'; game: number; color: KokakuZoneColor | null; czWon: boolean }
  /** タチコマSAMゾーン（200G/400G）。モード尤度には入れない */
  | { type: 'tachikoma-zone'; game: 200 | 400; czWon: boolean }
  /** 殲滅ポイント契機。モード尤度には入れない */
  | { type: 'zone-point'; color: KokakuZoneColor | null; czWon: boolean }
  | { type: 'cz-result'; czType: 'sam' | 'tachikoma'; success: boolean; visualHack: boolean | null }
  | { type: 'at-end'; route: 'cz' | 'direct' | 'ceiling' }
  /** 終了画面・裏コマンド画面。サイクル途中にも置ける */
  | { type: 'screen'; context: 'cz-end' | 'at-end' | 'ura-command'; screen: KokakuScreen }
  /** 未当選のまま打ち切った行。到達G数を右側打ち切りに使う */
  | { type: 'cycle-abandon'; game: number };

export interface KokakuMachine extends BaseMachine {
  machineType: 'kokaku';
  events: (KokakuEvent & { id: string; timestamp: number })[];
  /** 進行中サイクルの到達列を決めるために必要 */
  currentGame: number;
}
```

MonhanRise と同じく **サイクル回数・ゾーン回数は events から導出し、フィールドに持たない。**
`buildZoneGrid()` が尤度計算とまったく同じ規則でグリッドを組む。

`types/index.ts` が `export *` するので、イベント名・型名には `Kokaku` 接頭辞を必須にする。

## 9. 実装の段階分け

### Phase 1 — 実装済み（2026-09-26）

- 記録UI 一式（グリッド・CZ結果・AT記録・視覚HACK・終了画面/裏コマンド）
- **モード推測**: §3 の完全な期待度マップ ＋ CZ天井のハード制約 ＋ §4-4 の濃厚制約
- **設定推測**: §2-3 の CZ後モード移行率による事後確率（設定1〜6 完備）
- 他の設定差要素（§5-2〜5-7）は実測値と設定1/6基準の並記のみ。**%は出さない**

### Phase 2（数値が揃い次第）

- 殲滅ZONE色別CZ当選期待度（§5-4）の中間設定 → 最有力の追加軸
- 視覚HACK・タチコマCZ・リブートストックの中間設定
- 殲滅テーブル 40〜99pt 帯の色列
- 設定2〜5 の CZ確率・AT初当り・出玉率

### 調整の余地として残している点

- **ゾーン当否の独立仮定**（§3-3）。同時分布が公開されたら `cycleEmission` を差し替える
- **「濃厚」をハード制約にしている**（§4-4）。実戦で外れるようなら確率的な弱い制約に変える
- タチコマSAMゾーンの集計が「AT終了後限定」かどうか未確認（§3-2）。
  限定なら現在の集計は分母が過大になる
- 打ち切り（`cycle-end` で cz も at も無い行）の後は系列を切って次を均等事前にしている。
  同一台を続けて打つ運用が多いなら、切らない方が精度は出る

`kokaku_state` が無い状態で新クライアントを出すと、クラウド保存だけが黙って失敗する。
