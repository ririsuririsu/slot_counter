## 2. 規定ゲーム数と天井

### 2-1. ゲーム数の数え方 — AT間・CZ失敗でリセットされない

- 規定ゲーム数は **AT間** で数える。**CZ失敗ではリセットされない**（ユーザー確認済み）
- 筐体左の**サブ液晶にAT間のゲーム数が出る**。アプリのG数はすべてこのサブ液晶の値
- **液晶ゲーム数は設定変更時も電源OFF→ONでも0Gから表示される**。さらに設定変更時は
  内部ゲーム数がランダムに加算される

最後の点から、**朝一の1行目は表示Gと内部Gが一致しているか分からない**
（据え置きなら前日の続き、リセットならランダム加算）。ただし打ち手はG数の見当を付けられるので、
1行目の150Gも推定に使う（§4-3）。

## 4. 推定モデル

### 4-1. 軸

ユーザーの指定（2026-10-29）で、次の8要素を軸にした。

| 要素 | 扱い | 分布 | 分母 |
|---|---|---|---|
| 共通ベル | **事後確率** | 二項 | 手入力のトータルG数 |
| 変換高確移行（弱リコリス目） | **事後確率** | 二項（×0.9） | 「弱リコ目」カウンター（分子は「→高確」カウンター） |
| 変換高確移行（150G） | **事後確率** | 二項（×0.9） | グリッドの150G列で帯の結果を押した行（1行目を含む全行） |
| 直撃 | **事後確率** | 二項 | 手入力のトータルG数（ベルと同じ分母） |
| 天井短縮 | **事後確率** | カテゴリ（右側打ち切りあり） | ラッシュ50終了の次のサイクル |
| 終了画面 | 「濃厚」だけ**ハード制約**、示唆は集計表示 | — | — |
| サミートロフィー | **ハード制約**（すべて濃厚） | — | — |
| プロローグ・エピソードボーナス | 集計表示のみ | — | — |

各軸の対数尤度を足し、制約で除外した設定を −∞ にして、最後に1回だけ正規化する
（モンハンライズ・カバネリと同じ）。**事後確率に入れる5軸はすべて設定1〜6の公表値が揃っている。**

プロローグ・エピソードボーナス・終了画面の「示唆（弱/強）」は振り分けが非公開なので、
**数値を捏造せず回数だけ出す**（カバネリの発光率で起きた事故を繰り返さない）。

**AT初当り・CZ確率は軸にしていない（参考表示のみ）。** この2つは「ATの大半がCZ成功から来る」
ので強く相関し、直撃もAT初当りの一部なので、独立な軸として足すと同じ情報を二重に数える
（設定6 vs 1 で約1.5倍の過信）。今回の軸の組み合わせ（ベル・高確・直撃・短縮）は互いに重ならない。
将来AT初当りを軸に足すなら、直撃は「AT内の直撃率（AT確率/直撃確率）」に置き換える必要がある。

### 4-2. 変換高確 — 帯が出る割合 0.9 を掛ける

打ち手が観測できるのは**帯**で、**移行しても約10%は煽りが失敗して帯が出ない**（一撃）。
したがって観測される移行率は 0.9 × 公表値 になる。

| 設定 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 弱リコリス目（帯） | 34.5% | 34.5% | 35.2% | 36.9% | 38.7% | 40.4% |
| 150G（帯） | 45.0% | 45.0% | 45.0% | 49.2% | 52.7% | 56.3% |

**掛けないと設定6の実測が設定4〜5に見える。** 補正係数そのものは「約10%」としか
公表されていないので、`LYCORIS_BAND_VISIBILITY` の1か所に置いてある。

補正が実機と合っているかは、**設定差の無い契機**（50G・450G、どちらも移行率50%）
の帯出現率を推測タブの参考欄に出して確かめられる。約45%から大きく外れるなら、
帯の見落としか補正値のずれを疑う。

**弱リコリス目は独立した2つのカウンター**（「弱リコ目」＝分母、「→高確」＝分子）で数える
（ユーザー指定 2026-10-29。モンハンライズのライズゾーンと同じ作り）。

- 帯は引いた時点では分からない（煽りのあとに出る）。その間に次のレア役を引くこともあり、
  よくある流れは「レア役 → 高確（帯）→ 変換 → CZ → AT」。どの弱リコ目の結果かを紐づける必要が
  無いように、引いたときに「弱リコ目」、帯が出たときに「→高確」を別々に押す
- **高確中（帯が出ている間）に引いた弱リコリス目は分母に数えない**（移行が観測できないため）。ボタンに明記
- 分子 > 分母は数え間違いなので、軸を使わず警告する
- 当初は「レア役ごとに変換・帯の結果を記録し、あとから追記する」形を作ったが、設定推測に効くのは
  弱リコ目→高確だけなので、カウンターに置き換えた。チェリー・スイカ・強リコ目と、変換からのCZの
  紐づけは記録しない（変換からのCZはグリッドの「他」列に契機＝小役変換で入れられる）

150G など規定G数の高確（グリッドの高確列）は、**押した結果だけを使い、通過して空でも「帯なし」にしない**。
帯は液晶の隅に出るだけで見落としやすく、空を「帯なし」とすると見落としがそのまま低設定寄りの偏りになる。

### 4-3. 150G は1行目も使う

朝一は設定変更でも電源OFF→ONでも表示が0Gから始まり、内部G数と一致しない可能性がある（§2-1）。
当初はこれを理由に1行目の150Gを除外していたが、**打ち手はG数の見当を付けられる**ので
ユーザー指定（2026-10-30）で1行目も含めることにした。記録された150Gの結果をそのまま信用する。

- 途中から打った台で、打ち始めGより手前にある150Gは見ていない枠なので、グリッドがそもそも記録させない
- 1行目の0G列（引き戻し）は直前のATが無いので使わない。天井短縮も1行目は直前の終わり方が分からないので使わない。
  どちらも「G数が分からない」ではなく「その抽選が存在しない／条件が分からない」ための除外で、150Gとは理由が違う

**150Gの抽選は1サイクル1回**なので、同じ行に150Gを2回記録していたら最後に記録した方（訂正）だけを数える。
二重タップがそのまま尤度に入らないようにするため。参考欄の50G・450Gも同じ。

### 4-4. 天井短縮 — 右側打ち切りのカテゴリ分布

**直前のATが「ラッシュ50終了」だった行だけ**が対象（駆け抜け・上位CZ失敗は設定不問の短縮、
ラッシュW終了後は短縮抽選の有無が公表されていない）。1行目は直前が分からないので対象外。

| その行で分かったこと | 観測 | 尤度 |
|---|---|---|
| 短縮告知を見た（サブ液晶に短縮天井までのG数） | 短縮天井 c が確定 | π_s(c) |
| 短縮天井で当選（経路=短縮天井） | 短縮天井 c が確定 | π_s(c) |
| AT間天井（850G）で当選 | 短縮なしが確定 | 1 − Σπ_s |
| CZ成功で当選 | **そのCZに入ったG** T より M 以上手前の短縮は無かった | 1 − Σ_{c+M<T} π_s(c) |
| 直撃で当選 | AT当選G T より M 以上手前の短縮は無かった | 同上 |
| 進行中で告知なし | 使わない | — |

- **CZ成功の打ち切り位置はAT当選Gではなく、そのCZに入ったG**（CZの記録が無ければAT当選G）。
  CZに入ったGは、その行の最後の `cz` イベント（契機は問わない。規定G数・小役変換・スタンプ等）から取る
- **否定するのは c + M < T の短縮天井だけ**（M = `LYCORIS_SHORT_CEILING_MARGIN` = 50G）。
  短縮天井は「250G+α」で、+α（前兆とCZ消化）の範囲で入ったCZは**その短縮天井の成功濃厚CZだった
  可能性がある**。ゾーン（250/400/600/750）やCZ間天井600G+αと短縮天井のG数は重なっているので、
  余裕なしで否定すると高設定側の短縮を誤って消し、低設定に偏る（レビューで発覚。262Gの「その他CZ」や
  612GのCZ間天井CZが、それぞれ短縮250G・600Gを否定していた）。
  M は公表値ではなく保守側に取った値で、大きくするほど情報を捨てるが偏らない
- 否定できる短縮が1つも無い（T ≤ 250 + M）なら観測に数えない
- 進行中の行は前兆中の可能性があり、どこまで否定できるかを決められないので告知以外は使わない。
  セッション最後の行の情報は少し捨てている
- 750G は全設定共通 7.4% だが、確定・打ち切りの分母に効くので表からは外さない

### 4-5. 終了画面・トロフィーの制約

| 示唆 | 制約 |
|---|---|
| サミートロフィー 銅 / 銀 / 金 / キリン柄 / 虹 | 設定2以上 / 3以上 / 4以上 / 5以上 / 6 |
| 終了画面 押上の風景 / ロボ太 / ハワイ | 設定2以上 / 4以上 / 6 |
| **たきな私服 ＋ 千束ラッシュ終了**（ラッシュW終了を除く） | **設定4以上** |
| **千束私服 ＋ たきなラッシュ終了**（同上） | **設定4以上** |
| 私服（同じキャラのラッシュ・ラッシュW終了） | 表示のみ（高設定示唆・弱） |
| ドレスコード | 表示のみ（高設定示唆・強） |

**私服の意味は「どのラッシュが終わったか」で変わる。** そのため終了画面はATイベントの中に
ラッシュ種別・終わり方と組で持つ。判定は `lycorisCasualVariant` が4通りに分ける:

| 種類 | 条件 | 扱い |
|---|---|---|
| `w` | 終わり方＝ラッシュW終了（ラッシュ種別は問わない） | 弱示唆 |
| `unknown` | それ以外で、ラッシュ種別か終わり方が未入力 | 弱示唆として扱い、入力画面で警告 |
| `mismatch` | キャラと終わったラッシュが逆 | 設定4以上濃厚（制約） |
| `same` | キャラと終わったラッシュが同じ | 弱示唆 |

集計ではこの種類ごとに別の行に分ける（同じ画面でも制約になる行とならない行がある）。

制約はすべて「k以上」か「6」なので、積集合は必ず設定6を含み**制約どうしの矛盾は起こりえない**
（テストで不変条件として固定）。万一空になったら制約を丸ごと外して警告する（`settingConflict`）。

### 4-6. エピソードボーナスの EP3

EP3 の示唆は**同一ラッシュ内の1回目の選択時だけ**有効。ラッシュとラッシュWは別に数える
（ATイベントの `episodes` を選んだ順に持ち、ラッシュ/W それぞれの先頭かで判定）。
2回目以降の EP3 は「示唆なし」の別の行として集計する。

### 4-7. 効き方の目安

期待される log₁₀BF。ベル・直撃は通常1000Gあたり、それ以外は観測1回あたり。

| 比較 | ベル | 直撃 | 弱リコ目（1回） | 150G（1回） | 短縮（完全観測1回） |
|---|---|---|---|---|---|
| 設定6 vs 1 | 0.096 | 0.039 | 0.0033 | 0.011 | 0.044 |
| 設定6 vs 4 | 0.028 | 0.009 | 0.0011 | 0.004 | 0.010 |
| 設定4 vs 1 | 0.020 | 0.009 | 0.0006 | 0.002 | 0.011 |
| 設定6 vs 5 | 0.007 | 0.002 | 0.0003 | 0.001 | 0.003 |

- ベル＋直撃だけで設定6 vs 1 が BF=100 になるのに通常 約15,000G。
  弱リコリス目をすべて判別できたとすると（1/50.3）約10,000G
- **ベルが情報の柱。** 入力画面のカウンターの先頭に置いている
- 隣接設定の判別には使えない。設定1〜3はベルと150Gが同値で事実上分からない
- 濃厚示唆（トロフィー・終了画面）が1回出れば、上の数字より強く効く

### 5-2. 規定ゲーム数グリッド — 攻殻機動隊と同じ作り

ユーザー指定（2026-10-29）。**縦＝AT間サイクル / 横＝規定ゲーム数の固定列**。G数はセルの位置から決まるので入力しない。

```
        0    50   100  150  250  400  450  600  750 │ 他       │ AT
1回     ・   未   ・   未   ◎CZ  —    —    —    —  │ ＋       │ 268G CZ成功 千束 R50終了
2回     ・   未   ・   帯○ —    —    —    —    —  │ 180G 小役変換CZ │ 進行中 150G

凡例  ・ 通過・CZなし（CZ列）   未 通過したが帯を未入力（高確列）   — 未到達
      ◎CZ そのゾーンからCZ当選   帯○ / 帯× / ？  帯あり / 帯なし / 判別不能
```

| 列 | 種類 | セルを押したときの選択肢 | 空のときの扱い |
|---|---|---|---|
| 0 / 100 / 250 / 400 / 600 / 750G | CZ | CZ当選／（進行中の行）ここまで回した・到達Gを戻す | 通過済みなら **CZなし**（攻殻と同じく入力ゼロで観測） |
| 50 / 150 / 450G | 高確 | 帯あり / 帯なし / 判別不能 | **未入力**（推定に入れない。破線の「未」で入力を促す） |
| 他 | — | 規定G数以外のCZ（小役変換 / スタンプ / CZ間天井 / その他）・短縮告知。G数を入れる | — |
| AT | — | 当選G・経路・短縮天井・プロローグ ／ 終了: ラッシュ種別・終わり方・エピボ・終了画面・トロフィー | 進行中なら現在G |

- 列の空の扱いがCZと高確で違うのは意図的。CZは見落とさない大きな事象なので「空＝CZなし」で入力を省けるが、
  帯は見落としやすく「空＝帯なし」にすると低設定に偏る（§4-2）
- 規定G数の高確は 50/150/450G。300G は移行濃厚、650G は 25% で設定差なしなので列に置かない
- 1行目の行見出しを押すと打ち始めGを入れられる
- **到達Gは記録から導き、記録の追加で現在Gは書き換えない**（攻殻と同じ）。ストアで現在Gを引き上げると、
  誤って記録したマスを消しても到達Gが戻らず、通過済みのマス（CZなし）が広がったままになる（レビューで発覚）。
  AT当選で現在Gは0に戻る。進行中の行の到達Gは、記録とセルの「ここまで回した」だけで決まる（入力欄は無い）
- **見ていない枠には記録できない**: 1行目の打ち始めGより手前の列と、1行目の0G列（直前のATが無いので
  引き戻しが無い）は「未到達」扱い。締めた行でAT当選Gより先のマスと「他」列のG数も記録できない
  （起こりえない記録で、天井短縮の打ち切りを壊すため）
- 2行目以降の0G列は、1Gでも回せば通過済み（「ここまで回した」は1Gにする）
- AT当選時に分かるのは当選G・経路・プロローグまで。終了情報はAT終了後に、その行のAT列か
  お知らせからタップして追記する
- CZの成否はAT列の経路（CZ成功）で表すので、CZイベントには成否を持たせていない
- 締めた行のセルも押せる（記録はその行のATの直前に挿入）。過去の行への追記・訂正は現在Gを触らない
- **最後のATを取り消すと、そのAT当選Gを現在Gに戻す。** AT記録で現在Gを0にしているので、
  戻さないと行が進行中に戻ったときに到達Gが消える
- 1行目には「打ち始めG」がある。途中から打った台で、自分が見ていない列をグリッド上で未到達にするため

### 5-3. トータルG数は手入力（共通ベル・直撃の分母）

ユーザー指定（2026-10-30）。入力タブ上部の「トータルG数」に通常時の総G数を入れ、**共通ベルと直撃の分母**にする。
モンキーターン・カバネリと同じ共通のゲーム数入力（`totalGames` / `getMachineTotalGames` / `updateTotalGames` /
`GameInputModal`）を使う。

- 当初はグリッドの各行の `AT当選G − 開始G` の合計から通常G数を導いていたが、手入力に置き換えた。
  グリッドのG数（サブ液晶のAT間G）は規定ゲーム数の通過判定と天井短縮の打ち切りにだけ使う
- 直撃もベルと同じ「通常時G数あたりの確率」なので、同じトータルG数を分母にする（分母を分けると食い違う）
- 参考欄の AT初当り・CZ の分母もトータルG数
- **AT中のG数を含む値を入れると、ベル確率が低めに出て低設定寄りになる**（ベルは通常時のみ数えるため）

## 6. データモデル

```ts
export interface LycorisMachine extends BaseMachine {
  machineType: 'lycoris-recoil';
  bell: number;               // 共通ベル。頻度が高いのでイベントにせず回数だけ
  weakLycoris: number;        // 弱リコリス目（分母）。高確中に引いたものは数えない
  weakLycorisKoukaku: number; // そこから帯が出た回数（分子）。弱リコ目とは独立に押す
  startGame: number;          // 打ち始めのサブ液晶G（1行目の開始G）
  currentGame: number;        // 進行中サイクルのサブ液晶G。AT当選で0
  events: LycorisEvent[];
}

type LycorisEvent = (
  | { type: 'koukaku-zone'; game: 50|150|450; result: 'moved'|'stay'|'unknown' }
  | { type: 'cz'; game; trigger: 'zone'|'convert'|'stamp'|'cz-ceiling'|'other' }
  | { type: 'short-notice'; game; ceiling: 250|400|600|750 }
  | { type: 'at'; game; route: 'cz'|'direct'|'at-ceiling'|'short-ceiling'; shortCeiling;
      prologue; rush; outcome; episodes; endScreen; trophy }
) & { id: string; timestamp: number };
```

- サイクル数・CZ回数・AT回数は **events から導出し、フィールドに持たない**。
  トータルG数（`totalGames`）だけは手入力の値をそのまま持つ
- **保存するのは観測した事実、どの軸に入れるかは推定側が決める。** AT間天井がCZを経由するか
  （§3-3）や帯の補正値が後で変わっても、記録を作り直さずに済む
- `normalizeLycorisEvents` が読み込み境界。形の合わないイベントは落とすが、**ATは落とすと
  前後のサイクルが結合してしまう**ので、必須（game・route）が揃っていれば任意項目の壊れた値を null に寄せて残す
- G数は **0〜999 の整数**だけを受け付ける（小数・上限超えは落とす）。規定G数契機のCZは、
  G数が規定ゲーム数（0/100/250/400/600/750）でなければ落とす。台の `startGame`・`currentGame` は
  `normalizeLycorisGame` で0〜999に丸める（上限超えを通すと入力フォームの既定Gが上限超えになり、
  保存時の検証で黙って弾かれて「記録を押しても何も起きない」状態になる）
- ストアも保存前に同じ関数で検証する（`toLycorisEvent`）
- **`STORE_VERSION` = 16。** v14 の移行で localStorage のリコリス台を `normalizeLycorisMachineFields`
  で直す。正規化をクラウド読み込みだけに掛けていると、開発中に残った古い形の台
  （例: `episodes` の無いAT、`events` の無い台）がホーム画面の描画ごと落とし、アプリが起動しなくなる。
  その後、弱リコ目の2カウンター（v15）とトータルG数（v16）を足し、レア役イベントと650G列を廃止したので、
  v16 の分岐で同じ正規化（冪等）をやり直す。v14・v15 を刻んだ端末（プレビューで台を作った端末など）では
  項目が欠けたままになり、尤度が NaN で推定全体が黙って均等に化けるため
- クラウド読み込みは、状態行が無い（PGRST116）ときだけ空の台として読み、**それ以外の失敗は投げる**
  （カバネリと同じ）。黙って空の台を返すと、ダウンロードがローカルの記録を空で置き換え、
  次の自動同期でクラウドも消える。upsert の失敗も投げるので、手動アップロードで失敗が見える
- 一覧の key は添字（id は外部データ由来で重複しうる）
- `types/index.ts` が `export *` するので型名には `Lycoris` 接頭辞を付けている

## 9. 調整の余地として残している点

- **帯が出る割合 0.9** は「約10%」からの値。参考欄の帯出現率（設定差なしの契機）で検証できる
- **短縮天井の余裕 50G** は前兆＋CZ消化の見込みで、公表値ではない。前兆の長さが分かれば詰められる
- **弱リコリス目の設定2** は 38.3% を採用（サイト間で食い違い）
- **すでに高確中の弱リコリス目** は分母に数えない運用。帯が出なかった高確（約10%）の最中に
  引いた弱リコリス目は数えてしまいうるので、わずかに低設定寄りになる
- **弱リコ目と→高確は紐づけていない。** 帯が別の契機（チェリー・スイカ等）からの移行でも「→高確」を
  押すと分子が水増しされる。ボタンの注記（弱リコ目のあと帯が出たら）で運用している
- **ラッシュW終了後**は天井短縮の対象外にしている（公表なし）
- 直撃は「CZ非経由・天井以外」。AT間天井の当選を直撃にしないよう、経路は別に選ばせている
