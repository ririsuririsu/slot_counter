# カバネリ海門決戦：CZ記録と推定ポイント

2026-09-19追加。ユーザー指定の複合・高確チャンス目記録、無名／生駒CZ記録、当選時と現在の推定ポイント表示を実装する。

## 確認できた仕様と暫定換算

無名と生駒は独立したCZポイントを持つ。カバネは周期抽選用で、今回のCZポイントに混ぜない。複合役は含まれるキャラをそれぞれ記録する。

- [なな徹：今作のCZ抽選](https://nana-press.com/kaiseki/machine/1097/35413/)：各役の対応先、複合役、超高確・オールスターでのCZ当選、ST終了後の持ち越しを確認。無名・生駒の詳細な数値振り分けは掲載されていない。
- [パチマガ：今作のCZ抽選](https://cs62.cs-plaza.com/g/pachi/pla/s_conq/sammy_slot/224/tj03.php)：本前兆中のチャンス目が次回CZ分になることを確認。
- [実戦者のポイント換算例](https://note.com/kougaxxx/n/n159e2c9b677e)：通常の発光・高確単独を15pt、通常複合を15pt、高確複合を30ptとする前作基準の集計方法。今作の公式確定値としては扱わない。
- [発光率調査](kabaneri-flash-research.md)：非発光1pt／発光15ptという実戦集計を確認済み。

ユーザーは「推定ポイントとして表示する」方針を承認。採用する換算は以下。

| 無名・生駒の成立役 | 通常 | 対応キャラのカバネリ高確 |
|---|---:|---:|
| 単独・非発光 | 1pt | 15pt |
| 単独・発光 | 15pt | 15pt |
| 複合（2役） | 15pt | 30pt |
| 発光不明の通常単独 | 不明 | — |
| オールスター | 不明 | 不明 |
| 超カバネリ高確の対応役 | 不明 | 不明 |

例：無名＋生駒で無名だけ高確なら、無名30pt・生駒15pt。無名＋カバネなら無名だけCZポイントに加算する。オールスター・超高確の減算量には断定できる根拠がないため、30／60／150ptなどの数値を当てはめない。自動でCZを記録せず、告知確認後にユーザーが入力する。

画面は「換算蓄積」と表記し、不明分を「＋不明」と併記する。内部値、規定ポイント、CZまでの残りポイントではない。150pt天井は未確定のため上限・自動リセット・残りゲージは設けない。

## 入力と集計

- 単独役はキャラごとに左から「高確（帯付き）・発光中・発光・非発光」の丸ボタンを並べ、1つだけタップして記録。「発光」は成立も同時に1回増える。表示回数は高確単独の履歴件数、通常単独で発光判別できない履歴件数、発光回数、非発光回数（成立−発光）。ボタン内のキャラ名は省き、行タイトルと色で区別する。「発光中」は既に光っていて判別できない役として発光率から除外し、ポイント換算不明で保存する。高確中は「高確」を優先する。
- 複合は「複合入力」をONにし、各キャラの丸ボタンを「高確・通常」の2択に切り替える。2キャラ以上を選択してまとめて1件として記録。複合は対応役が発光する運用のため、発光を別途選ばせない（保存値は発光あり・発光率対象外）。金色の枠・背景・「複合入力中」の表示でモードを示し、選択した丸ボタンに枠とチェックを付ける。各キャラは1つまで選択でき、同じボタンで解除、別のボタンで状態変更。高確は30pt、通常は15ptに換算する。3キャラ選択はオールスターとして換算不明にする。超高確を含む複合は詳細入力を使用。確定後は自動OFF、手動OFFは未確定の選択を破棄する。
- 複合入力のON／OFFで説明文や余白を上部へ追加しない。高確ボタンと通常ボタン（非発光の位置）は座標とサイズを保ち、使わない列は空けておく。下部の操作欄も高さを確保し、切替時の配置ずれを防ぐ。
- 「高確」はカバネリ高確の単独役用。超高確単独・前兆中・発光不明などは「詳細入力」から記録する。高確・複合・詳細入力は発光率の分子・分母に入れない。
- 「直前を取消」はこの入力画面で最後に追加したイベントだけを削除する。減算モードでは、通常役は従来の対応カウント、高確・複合は指定した役・状態に一致する直近の履歴を取り消す。スクロール中の指移動やキャンセルでは記録しない。キーボードのEnter／Spaceでも1回ずつ記録できる。
- 無名CZ・生駒CZは別々に記録する。昇格した側には「銅藍へ昇格」を付けられる。一方のCZを記録しても他方の蓄積は消さない。
- 当選契機を選択すると、その役の直後にCZイベントを挿入し、それ以降に引いた役を次回分へ残す。選択可能なのは同キャラの直近CZまたは集計開始より後の対応役のみ。
- 当選契機が分からない場合は告知時までを概算で区切る。内部的な当選ゲームや前兆の長さを自動判定しない。
- CZ履歴は区間ごとの換算ptを表示。平均pt/CZは開始点が分かり、成立記録があり、不明換算を含まない完了区間のみを使用する。進行中・途中開始・成立記録なしの区間は平均から除外。
- 追加前のカウンターから成立順・過去CZを復元しない。初回は「開始前の蓄積不明」。CZ後は0から次の区間を計測する。「ここから集計を開始」で途中開始／0pt開始を選択できる。ST終了のみではリセットしない。
- 操作履歴の削除で全区間を再計算する。従来の減算ボタンは対応する直近の通常成立／発光イベントを取り消し、カウンターも戻す。旧カウントしかない分は従来どおり減らし、架空のポイント履歴は作らない。
- 「新規記録」は既存仕様どおり別IDを作る。以前のCZ履歴は旧記録に残る。

チャンス目と下段ベルを最上部の同じ入力エリアに集約し、CZポイント・履歴はその下へ配置する。下段ベルは見出し付きの130px丸ボタンを維持。iPhone 12相当の390px幅、ブラウザUIを考慮した664pxの表示領域で全入力ボタンが収まることを確認。入力方法の説明は折りたたみ、複合ON／OFF時もベル・チャンス目の座標を保つ。

## 保存・公開手順

`KabaneriMachine.czEvents` に順序付きイベント列を保存。localStorageはversion 11へ移行し、既存台には空配列を補完する。読込時も履歴なしを許容する。

クラウドでは `machine_counters.kabaneri_events`（JSONB）へカウンターと一緒に保存する。DB更新は [20260919000000_add_kabaneri_cz_events.sql](../supabase/migrations/20260919000000_add_kabaneri_cz_events.sql)。**新クライアントを本番公開する前にこのマイグレーションを適用する。** 2026-09-19、本番反映の指示により適用済み。公開アプリの参照先とリンク済みDBの一致、およびリモートのマイグレーション履歴を確認した。

手動同期で履歴保存に失敗した場合はエラーを返す。古いDBに履歴列がないまま復元してローカル履歴を空にすることを避けるため、復元もエラーにする。旧行は列追加時の既定値 `[]` で読める。自動同期の再送・競合解決は既存アプリ同様、手動同期で補う。

検証：`npm run test:kabaneri`。ポイント換算、複合の片側高確、CZの遡及入力、同時契機、履歴削除、旧保存データ移行、クラウドへの往復と失敗を実ソースで検証（外部通信はモック）。
